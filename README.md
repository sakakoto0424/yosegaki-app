# 寄せ書きアプリ

**2026年度 夏休みの自由研究（中学2年生）**

みんなで1枚の共有キャンバスに書き込んでいく、Web版の寄せ書きサービスです。
テーマ（例：「体育祭2年5組」など）を作成し、参加者がペンで描いたり文字を置いたりして書き足していきます。

---

## 自由研究レポート

### テーマ

夏休みが終わりそうだったのでAIに丸投げして寄せ書きサイトアプリを作ってみた

### 概要

中学2年の夏休み、自由研究のテーマを決めないまま夏休み終盤に差し掛かってしまった。そこで、AI（Claude Code）に開発を全面的に任せる形で、全校生徒が使える「寄せ書きWebアプリ」を制作することにした。テーマ（体育祭のクラス、合唱コンクールなど）ごとに1枚の共有キャンバスを作り、みんなで書き足していける仕組みで、無料のクラウドサービスだけを使い、実際にインターネット上で誰でもアクセスできる形で公開するところまで実施した。

### 研究目的

- 「言葉で指示を出すだけで、AIはどこまでソフトウェアを作れるのか」を実際に体験・検証する
- 全校生徒が使える、実用的な寄せ書きWebサービスを完成させる
- 開発を進める中で、AIとどのようにやり取りすれば「欲しいもの」に近づけられるのかを学ぶ

### 研究方法

1. 作りたいものの要件をAIに伝える（全校生徒が使える／テーマ別に作成できる／テキスト・手書き両対応／基本無料／学校のiPadでも指で書ける）
2. AIが提案する技術（使うサービスやプログラミング言語）を確認しながら、一緒に方針を決める
3. 実際に動くもの（試作品）をこまめに確認し、気づいた問題点・直したい点をAIに伝えて修正してもらう、を繰り返す
4. 最終的に本番のインターネット環境に公開し、実機（自分のスマートフォンなど）でも動作を確認する

### 結果

#### 最終的に完成した機能

- テーマの作成・選択（例：「2026年度体育祭2年5組」）
- 1つのテーマ＝1枚の共有キャンバス。みんなが同じ絵の上に直接書き足していく方式
- ペンで書く（指・マウス・タッチペン対応）
- 文字を置く（好きな位置に文字を配置）
- 写真を貼る（アップロードした写真をドラッグで移動・スライダーで拡大縮小してから配置）
- 9色から選べるカラーパレット
- 広いキャンバス（矢印ボタンでスクロール移動、実物の色紙のように画面ごと回転も可能）
- 保存前の書き込みを取り消せる「やり直す」機能
- 寄せ書きのダウンロード（書き込みがある範囲だけ自動でトリミング）
- 無料利用枠を守るための上限（投稿数・画像サイズ）
- ID・パスワードによるアクセス制限（Basic認証）

#### 開発の流れ（要約）

1. GitHub・Cloudflareのアカウントを用意し、Rust（Leptos）+ Cloudflare Workers/D1/R2という構成でアプリの土台を作成
2. 手書きキャンバス、テーマ作成、投稿機能を順番に実装し、本番環境へ公開
3. 「投稿が独立していて寄せ書きらしくない」という指摘を受け、テーマ＝1枚の共有キャンバスという設計に大きく作り直し
4. 「キャンバスサイズが固定で余白が心配」という指摘を受け、キャンバスを拡張しスクロール機能を追加
5. Basic認証、カラーパレット、写真アップロード、画面回転など、使いながら欲しくなった機能を追加
6. 実際の利用を想定した確認の中で見つかった不具合（iPhoneで描けない、写真付きの保存が失敗する等）を調査・修正

#### 開発中に見つかった不具合と原因

| 不具合 | 原因 |
|---|---|
| iPhoneでペンが描けないことがある | スクロール可能な表示枠に付けていた設定が、iOS特有の「指のタッチをスクロール処理が横取りしてしまう」問題を起こしていた |
| 写真を含めた寄せ書きがダウンロードに反映されない | 写真データを保存する際、サーバー側の仕組み（Axum）のリクエストサイズの初期上限（2MB）を超えてしまい、保存自体がエラーで失敗していた（画面の小さな表示にしか出ないため気づきにくかった） |

いずれも、実際に動かして確認する中で見つかり、原因を調べた上で修正した。

### 考察

- AIに「丸投げ」したとはいえ、実際には**具体的な指示や指摘（フィードバック）を出すほど、良いものに近づく**ことがわかった。特に「寄せ書きらしくない」といった感覚的な指摘でも、AIはそれを咀嚼して具体的な設計変更（1枚の共有キャンバス化）に落とし込むことができた。
- 実際に動くものをこまめに確認しながら進めたことで、見た目だけでは気づかない不具合（iPhoneでの描画不良、写真保存の失敗）を早い段階で発見・修正できた。もし最後まで確認せずに公開していたら、使う人が困っていたはずである。
- 完全な「丸投げ」というよりも、「使ってみて気づいたことを伝える」というAIとの共同作業に近い体験だった。何を作りたいか・何がおかしいかを的確に伝える力が、成果物の質を大きく左右すると感じた。

### 結論

中学生でも、AIに指示を出すことで、実用的なWebアプリケーションを短期間で完成させることができた。ただし、それは「何もせずに任せきり」という意味ではなく、「作りたいものを言葉で伝え、出来上がったものを試し、気づいたことを伝え直す」という繰り返しの積み重ねによって実現したものである。AIはあくまで道具であり、使う人間の目的意識とフィードバックの質が、最終的な成果物の質を決めるということを、この自由研究を通じて学んだ。

### 工夫したこと・アピールポイント

- 本物の寄せ書き（1枚の紙にみんなの字や絵が同居する）に近づけるため、途中で設計を作り直してでも「投稿を独立させず、1枚の共有キャンバスに全員が書き足す」形にこだわった
- 学校のiPadやスマートフォンでも指で書けるよう、タッチ操作にしっかり対応した（実際に不具合が見つかった際も原因を調べて修正した）
- キャンバスが固定サイズで手狭にならないよう、広いキャンバス＋スクロール移動＋回転表示に対応した
- 無料のサービスだけで完結させつつ、投稿数や画像サイズの上限（リミッター）を自分で設計し、無料枠を超えないよう配慮した
- Basic認証でアクセス制限をかけ、誰でも荒らせる状態にはしないようにした
- 写真アップロード、ペンの色選択、画面回転など、実際に「みんなで使う場面」を想像しながら機能を追加していった
- 問題が見つかるたびに、実際の操作に近い自動テストを行い、「本当に直っているか」を確かめてから公開するようにした

## 主な機能

- テーマの作成・選択
- 1テーマ＝1枚の共有キャンバス（参加者が同じ絵の上に直接書き足す方式）
- ペンツール（マウス・指・タッチペン対応、iPadなどのタッチ操作にも対応）
- 文字を置くツール
- 書き加えて保存
- 保存前の未保存分だけを取り消す「やり直す」機能
- 広いキャンバス（スクロールして移動しながら書ける）
- 寄せ書きのダウンロード（書き込みがある範囲だけを自動でトリミング）
- 投稿数・画像サイズの上限（無料利用枠を超えないための制限）
- Basic認証によるアクセス制限

## 技術スタック

- 言語: [Rust](https://www.rust-lang.org/)
- フロントエンド: [Leptos](https://leptos.dev/)（WebAssemblyにビルド）
- 実行環境: [Cloudflare Workers](https://developers.cloudflare.com/workers/)
- データベース: [Cloudflare D1](https://developers.cloudflare.com/d1/)
- 画像ストレージ: [Cloudflare R2](https://developers.cloudflare.com/r2/)

## セットアップ

以下のツールが必要です。

```sh
rustup target add wasm32-unknown-unknown
cargo install --locked cargo-leptos
cargo install worker-build
```

Cloudflareアカウントへのログインも必要です。

```sh
npx wrangler login
```

### 環境変数（Basic認証）

ローカル開発時は、リポジトリ直下に `.dev.vars` ファイル（Git管理対象外）を作成し、以下を設定してください。

```
BASIC_AUTH_USER=（任意のユーザー名）
BASIC_AUTH_PASS=（任意のパスワード）
```

本番環境では、以下のコマンドでシークレットとして設定します（値はコマンド実行時に入力します）。

```sh
npx wrangler secret put BASIC_AUTH_USER
npx wrangler secret put BASIC_AUTH_PASS
```

### D1データベースのマイグレーション

```sh
# ローカル
npx wrangler d1 migrations apply yosegaki-db --local

# 本番
npx wrangler d1 migrations apply yosegaki-db --remote
```

npx wrangler dev
